**Transcript:** Using the Scene Graph The scene graph is a hierarchical structure that represents the scene generated by stepping through the recipe up to the node in the Node Graph with the blue square. The node with the blue square is sometimes referred to as the view node , this is because the scene graph is just a view of the 3D scene generated up to that node. The information within the Scene Graph tab contains (but is not limited to) geometry, materials, lights, cameras, and render settings. Each node within the Node Graph tab describes a step within the recipe, which adds, deletes, or modifies scene graph locations or scene graph data. Scene graph data is stored as attributes on locations. Scene Graph Terminology The selected location has a path of /root/materials . • Parent - the location /root is the parent of /root/materials . • Child - the location /root/materials/Material is a child of /root/materials . • Sibling - the location /root/world is a sibling of /root/materials . • Leaf - the location /root/world/geo/primitive is a leaf location. A leaf is a location with no children. • Branch - the locations /root/world and /root/materials are two branches from /root . Locations within Katana have a special attribute called type . This attribute tells Katana what type of information to expect at that location. In the example above, there are five group locations and one geometry material location. Viewing the Scene Graph You can view the scene graph generated at any node within the Node Graph . This shows the 3D scene generated by the recipe up to that point. To view the scene graph at a particular node: 1. Select the node in the Node Graph . 2. In the Node Graph , select Edit View Selected Node . OR 1. Hover the mouse over the node. 2. Press the V key. This node is known as the view node . If the node moves off the screen, or is hidden within another node, its location is indicated by a small blue triangle. Navigating the Scene Graph History Katana keeps a history of the view node that can be traversed. To go back and forward through the history, use the icons in the upper-left area of the Scene Graph tab. ## Structured Notes

### Core Technique
The scene graph is a **view**, not a document: it shows the 3D scene as generated by running the recipe up to the node carrying the blue square (the **view node**), with all data stored as attributes on locations.

### Summary
This is the orientation page the skill was missing — the one that makes every other Katana entry legible. Each node in the Node Graph is a step in a *recipe* that adds, deletes or modifies scene graph locations or the attributes on them, and the Scene Graph tab shows the result up to whichever node holds the **view flag**. The vocabulary is defined precisely (parent, child, sibling, **leaf** = a location with no children, **branch**), every location carries a special **`type`** attribute telling Katana what to expect there, and the **Attributes tab is read-only** — you change attributes by changing the recipe, not by editing the panel. The page also introduces **implicit resolvers**, which is the concept that explains Katana's whole performance posture: expensive procedures like copying material and texture detail onto a location are *deferred* until the renderer needs them, which speeds up scene generation and — the more important half — keeps everything editable at a high level, so you change *which* material is assigned rather than overriding every shader value individually.

### Key Steps
1. Read the hierarchy with the standard terms: `/root` is the **parent** of `/root/materials`; `/root/materials/Material` is its **child**; `/root/world` is a **sibling** of `/root/materials`; `/root/world/geo/primitive` is a **leaf**; `/root/world` and `/root/materials` are two **branches** from `/root`.
2. Check a location's **`type`** attribute — it declares what kind of information lives there (group, geometry material, and so on).
3. **Set the view node** to see the scene at any point in the recipe: select the node and choose **Edit › View Selected Node**, or hover it and press **`V`**, or click the faint square to the left of the node.
4. Find the view node by its **blue square** — and when it is off-screen or hidden inside another node, by the **small blue triangle** that indicates its direction.
5. Walk the **view-node history** with the back/forward icons in the upper-left of the Scene Graph tab.
6. Inspect a location's data by selecting it and reading the **Attributes tab** — read-only by design.
7. **Turn on implicit resolvers** when you need to see the resolved result (material and texture copies) rather than the deferred, high-level state.

### Nodes / Tools / Settings
- **View node** — marked by a **blue square**; off-screen indicator is a **blue triangle**. Set via **Edit › View Selected Node**, the **`V`** key, or the faint square beside the node.
- **Scene Graph tab** (the view), **Attributes tab** (read-only attribute inspector), **Node Graph tab** (the recipe).
- Terminology: parent, child, sibling, **leaf** (no children), **branch**; the per-location **`type`** attribute.
- **Implicit resolvers** — deferred procedures (copying material detail, copying texture detail) run when the renderer needs them; toggled on from the Scene Graph tab.
- Canonical paths: `/root`, `/root/world`, `/root/materials`.
